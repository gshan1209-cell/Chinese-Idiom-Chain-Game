# 成語填字輸入格自動跳轉設計規格

## 0. 文件資訊

- 文件版本：v1.0
- 日期：2026-08-05
- Repository：`gshan1209-cell/Chinese-Idiom-Chain-Game`
- 功能名稱：成語填字輸入格自動跳轉
- 適用範圍：第一章縱橫成語填字主玩法
- 核准狀態：已核准

## 1. 設計摘要

玩家在候選字池點選任一文字並填入目前選取格後，系統必須自動選取下一個適合輸入的空格，減少逐格點選的操作成本。

本功能採用以下定案：

1. 無論填入文字正確或錯誤，都會自動跳到下一格。
2. 正確文字維持綠色狀態；錯誤文字保留在原格並顯示紅色。
3. 跳轉優先沿目前成語方向前進。
4. 原方向沒有可填格時，優先轉入相交成語。
5. 沒有相連候選時，選擇盤面中距離最近的空格。
6. 盤面仍有空格時，先走完所有空格，不回訪已有文字的錯誤格。
7. 所有空格都有文字但仍有錯誤時，跳到第一個錯誤格。
8. 全部答案正確時取消選取並進入既有過關流程。

## 2. 設計目標

- 讓手機使用者可以連續點選候選字，不必每填一格就重新點盤面。
- 保留錯字可見性，讓玩家先完成整體盤面，再回頭修正。
- 在縱橫交叉盤面中維持可預測、穩定且可測試的跳轉順序。
- 將跳轉規則維持在純 TypeScript `puzzle-engine`，React 僅呈現新的 `selectedCellKey`。

## 3. 非目標

本階段不加入：

- 拖曳文字到方格。
- 手勢滑動切換方向。
- 使用者自訂跳轉方向。
- 鍵盤方向鍵巡覽。
- 動畫路徑或鏡頭移動。
- 自動清除錯字。

## 4. 名詞

### 4.1 可填格

符合以下條件的盤面格：

- 存在於 `PuzzleBoard.cells`。
- 不是固定提示格。
- 關卡尚未完成。

### 4.2 空白格

目前尚未填入文字的可填格。一般自動跳轉只會選擇空白格。

### 4.3 錯誤格

已填入文字，但目前文字不等於答案的可填格。只有當盤面不存在任何空白格時，錯誤格才會成為跳轉目標。

### 4.4 目前成語方向

目前選取格可能屬於一個或兩個 `PuzzlePlacement`。系統需要根據上一次選取與跳轉來源保留偏好 placement，優先沿該成語方向移動。

## 5. 核心跳轉規則

每次 `placePuzzleTile` 成功寫入一個可用字牌後，不論答案正確與否，都執行一次自動跳轉。

### 5.1 第一優先：同一成語向前

- 橫向 placement：由目前格向右搜尋。
- 直向 placement：由目前格向下搜尋。
- 自動略過固定提示格、已有文字的格子與已填正確格。
- 遇到第一個空白格立即選取。
- 不循環回到同一成語起點。

### 5.2 第二優先：交叉成語

若目前格屬於兩個 placement，且偏好 placement 已沒有空白格：

- 切換到另一個相交 placement。
- 從交叉格之後向該 placement 的正向搜尋。
- 略過固定提示格與已有文字的格子。
- 若正向沒有空白格，可搜尋該 placement 中其他空白格，依 placement 內順序選取第一格。

### 5.3 第三優先：相連未完成成語

若目前格所屬 placement 均已沒有空白格：

- 尋找與目前 placement 透過交叉格直接相連的 placement。
- 只選擇空白格。
- 優先選擇距離目前格最近的空白格。
- 距離相同時，以 row 較小、再以 column 較小者優先，確保結果穩定。

### 5.4 第四優先：全盤最近空白格

若沒有相連候選：

- 在全盤搜尋空白格。
- 使用曼哈頓距離：`abs(rowA-rowB) + abs(columnA-columnB)`。
- 距離相同時依 `row`、`column` 升冪決定。

### 5.5 第五優先：回到錯誤格

只有在所有可填格都已有文字，且至少一格答案錯誤時：

- 選取排序後第一個錯誤格。
- 排序依 `row`、`column` 升冪。
- 玩家可直接選擇另一個候選字覆蓋。

### 5.6 關卡完成

若全部可填格答案正確：

- `status` 設為 `completed`。
- `selectedCellKey` 設為 `null`。
- `preferredPlacementId` 設為 `null`。
- 不再執行任何跳轉。
- React 沿用既有過關畫面。

## 6. 填錯行為

- 錯字仍寫入 `values`。
- `mistakes` 加一。
- 分數沿用既有扣分規則。
- 原格顯示紅色錯誤狀態。
- 系統立即跳到下一個空白目標格。
- 不自動回收或移除錯字使用的字牌。
- 玩家點回錯誤格，或盤面空格全部填滿後由系統巡回錯誤格時，可用其他未使用字牌覆蓋。

## 7. 手動選格與方向偏好

玩家手動點選任一可填格時：

- 該格立即成為 `selectedCellKey`。
- 系統重新推導該格所屬 placement。
- 若只有一個 placement，該 placement 成為偏好方向。
- 若有兩個 placement，優先沿尚未解決格較多的 placement。
- 若未解決數量相同，優先使用橫向 placement，確保規則穩定。

自動跳轉後，下一次填字延續目前偏好 placement；只有該方向走完或玩家手動選格時才重新判定。

## 8. 領域模型調整

`PuzzleSession` 新增：

```ts
readonly preferredPlacementId: string | null;
```

用途：

- 保存目前自動跳轉偏好的成語 placement。
- 避免只依座標猜測方向，造成交叉格跳轉不穩定。
- 建立 Session 時依第一個可填格推導初始值。
- 清空盤面後重新推導。
- 關卡完成時設為 `null`。

此欄位只存在遊戲中的 Session，不寫入 IndexedDB 進度資料，因此不需升級 progress schema。

## 9. 純函式介面

在 `src/puzzle/puzzle-engine.ts` 新增：

```ts
findNextPuzzleCell(
  session: PuzzleSession,
  currentCellKey: string,
  preferredPlacementId: string | null
): {
  readonly cellKey: string | null;
  readonly preferredPlacementId: string | null;
};
```

函式不得：

- 修改傳入 Session。
- 依賴 React、DOM 或瀏覽器尺寸。
- 使用非決定性亂數。

## 10. 資料流程

1. 玩家手動選格或沿用目前選取格。
2. 玩家點選候選字。
3. `placePuzzleTile` 驗證字牌可用並寫入目前格。
4. 重新計算正確格數與關卡狀態。
5. 若已完成，取消選取與方向偏好。
6. 若未完成，呼叫 `findNextPuzzleCell`。
7. 更新 `selectedCellKey` 與 `preferredPlacementId`。
8. React 依新 Session 自動高亮下一格。

## 11. 例外與邊界行為

- 沒有選取格：不填字、不跳轉。
- 關卡已完成：不填字、不跳轉。
- 固定格或不存在的格：維持原 Session。
- 字牌不存在或已被使用：維持原 Session。
- 覆蓋目前格時，先釋放原字牌，再使用新字牌，之後才跳轉。
- 盤面資料異常導致找不到 placement 時，退回全盤最近空白格規則。
- 只有一個空白格且就是目前格時，維持選取目前格。
- 提示功能維持既有語意：提示填入哪一格，就選取該格；本次不讓提示自動前進。

## 12. 測試需求

至少新增以下自動測試：

1. 填對後沿橫向跳到右側下一個空白格。
2. 填錯後原格保留錯字，但仍跳到下一格。
3. 自動略過固定提示格。
4. 自動略過已填正確格。
5. 目前方向完成後切換到交叉 placement。
6. 交叉 placement 正向沒有候選時，選擇該 placement 其他空白格。
7. 非交叉端點完成後，選擇直接相連 placement 的空白格。
8. 無相連候選時選擇曼哈頓距離最近空白格。
9. 距離相同時依 row、column 穩定排序。
10. 盤面仍有空白格時不回訪錯誤格。
11. 所有格已有文字但仍有錯誤時跳到第一個錯誤格。
12. 最後一格填對後 `selectedCellKey` 與 `preferredPlacementId` 都為 `null`。
13. 手動選交叉格時依未解決數量推導方向。
14. 未解決數量相同時橫向優先。
15. 覆蓋錯字後原字牌回到候選池，並繼續跳轉。
16. 移除、提示與清空後方向狀態一致。

既有 puzzle、progress、打地鼠與 PWA 測試必須全部維持通過。

## 13. 驗收標準

- 使用者可連續點選候選字完成多格輸入，不需逐格點盤面。
- 填錯後仍立即移動，錯字留在原格顯示紅色。
- 跳轉順序在相同 Session 下完全一致。
- 不會跳到固定格或已填正確格。
- 有空白格時不會提前回到錯誤格。
- 交叉格可依偏好方向順暢前進並在走完後轉向。
- 全部填完但有錯時自動回到錯誤格。
- 全部正確時正常進入既有過關與星級流程。
- `npm run test`、`npm run typecheck`、`npm run lint`、`npm run build` 全部通過。

## 14. 範圍限制

本次只修改填字盤面選取與 Session 跳轉行為，不變更：

- 關卡資料與答案。
- 星級計算規則。
- IndexedDB 進度格式。
- 自由接龍與打地鼠模式。
- 候選字視覺設計。
