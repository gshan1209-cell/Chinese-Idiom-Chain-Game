# 成語填字輸入格自動跳轉設計規格

## 0. 文件資訊

- 文件版本：v1.1
- 日期：2026-08-05
- Repository：`gshan1209-cell/Chinese-Idiom-Chain-Game`
- 功能名稱：成語填字輸入格自動跳轉
- 適用範圍：第一章縱橫成語填字主玩法

## 1. 設計摘要

玩家在候選字池點選任一文字並填入目前選取格後，系統必須自動選取下一個適合輸入的空格，減少逐格點選的操作成本。

本功能採用以下定案：

1. 無論填入文字正確或錯誤，都會自動跳到下一格。
2. 正確文字維持綠色；錯誤文字保留在原格並顯示紅色。
3. 第一階段優先走完所有尚未填字的空格，不會過早跳回紅色錯字格。
4. 跳轉優先沿目前成語方向前進。
5. 原方向沒有空格時，優先轉入相交成語。
6. 沒有相連空格時，選擇盤面中距離最近的空格。
7. 全部空格都有文字後，才開始依固定順序巡回錯誤格。
8. 全部答案正確時取消選取並進入既有過關流程。

## 2. 設計目標

- 讓手機使用者可以連續點選候選字，不必每填一格就重新點盤面。
- 讓玩家先快速填完整體盤面，再集中修正紅色錯字。
- 在縱橫交叉盤面中維持可預測、穩定且可測試的跳轉順序。
- 將跳轉規則維持在純 TypeScript `puzzle-engine`，React 僅呈現新的選取狀態。

## 3. 非目標

本階段不加入：

- 拖曳文字到方格。
- 手勢滑動切換方向。
- 使用者自訂跳轉方向。
- 鍵盤方向鍵巡覽。
- 動畫路徑或鏡頭移動。
- 自動清除錯字。

## 4. 名詞

### 4.1 可填格

符合以下條件的盤面格：

- 存在於 `PuzzleBoard.cells`。
- 不是固定提示格。
- 關卡尚未完成。

### 4.2 空格

可填格目前尚未存在於 `session.values`。

空格是第一階段自動跳轉的唯一一般目標。已填入正確或錯誤文字的格子都不會在第一階段被重新選取。

### 4.3 錯誤格

可填格已存在文字，但文字不等於答案。

只有在盤面已無任何空格時，錯誤格才會成為自動跳轉目標。

### 4.4 已完成格

可填格的目前文字等於答案。已完成格不會成為自動跳轉目標。

### 4.5 目前成語方向

目前選取格可能屬於一個或兩個 `PuzzlePlacement`。系統需要保留偏好 placement，優先沿該成語方向移動。

## 5. 核心跳轉規則

每次 `placePuzzleTile` 成功寫入一個可用字牌後，不論答案正確與否，都執行一次自動跳轉。

跳轉分成兩個階段：

1. **填滿階段**：盤面還有空格時，只尋找空格。
2. **修正階段**：盤面沒有空格但仍有錯誤格時，才巡回錯誤格。

### 5.1 第一優先：同一成語向前找空格

- 橫向 placement：由目前格向右搜尋。
- 直向 placement：由目前格向下搜尋。
- 自動略過固定提示格、已完成格與已填錯誤格。
- 遇到第一個空格立即選取。
- 不循環回到同一成語起點。

### 5.2 第二優先：交叉成語找空格

若目前格屬於兩個 placement，且偏好 placement 已沒有空格：

- 切換到另一個相交 placement。
- 從交叉格之後向該 placement 的正向搜尋。
- 略過固定提示格與所有已填字格。
- 若正向沒有空格，可搜尋該 placement 中其他空格，依 placement 內順序選取第一格。

### 5.3 第三優先：相連成語找空格

若目前格所屬 placement 均已沒有空格：

- 尋找與目前 placement 透過交叉格直接相連的 placement。
- 只考慮該相連 placement 中的空格。
- 優先選擇距離目前格最近的空格。
- 距離相同時，以 row 較小、再以 column 較小者優先。

### 5.4 第四優先：全盤最近空格

若沒有相連空格：

- 在全盤搜尋空格。
- 使用曼哈頓距離：`abs(rowA-rowB) + abs(columnA-columnB)`。
- 距離相同時依 `row`、`column` 升冪決定。

### 5.5 第五優先：巡回錯誤格

只有在全盤沒有空格、但至少存在一個錯誤格時：

- 將錯誤格依 `row`、`column` 升冪排序。
- 優先選取目前格之後的第一個錯誤格。
- 若目前格已是排序中的最後一個錯誤格，循環回第一個錯誤格。
- 若目前填入動作已修正最後一個錯誤格，直接進入完成流程，不再循環。

此規則讓玩家填完整盤面後，可以依穩定順序逐一修正紅色格。

### 5.6 關卡完成

若全部可填格答案正確：

- `status` 設為 `completed`。
- `selectedCellKey` 設為 `null`。
- `preferredPlacementId` 設為 `null`。
- 不再執行任何跳轉。
- React 沿用既有過關畫面。

## 6. 填錯行為

- 錯字仍寫入 `values`。
- `mistakes` 加一。
- 分數沿用既有扣分規則。
- 原格顯示紅色錯誤狀態。
- 系統立即跳到下一個空格。
- 只要盤面仍有空格，就不會自動跳回已填錯誤格。
- 不自動回收或移除錯字使用的字牌。
- 玩家仍可隨時手動點回紅色格提前修正。

## 7. 手動選格與方向偏好

玩家手動點選任一可填格時：

- 該格立即成為 `selectedCellKey`。
- 系統重新推導該格所屬 placement。
- 若只有一個 placement，該 placement 成為偏好方向。
- 若有兩個 placement，優先沿剩餘空格較多的 placement。
- 若空格數量相同，優先使用橫向 placement。
- 若兩個 placement 都沒有空格，優先沿錯誤格較多的 placement。
- 若錯誤格數量也相同，仍以橫向 placement 優先。

自動跳轉後，下一次填字延續目前偏好 placement；只有該方向走完、切換交叉 placement 或玩家手動選格時才更新偏好。

## 8. 領域模型調整

`PuzzleSession` 新增：

```ts
readonly preferredPlacementId: string | null;
```

用途：

- 保存目前自動跳轉偏好的成語 placement。
- 避免只依座標猜測方向，造成交叉格跳轉不穩定。
- 建立 Session 時依第一個可填格推導初始值。
- 清空盤面後重新推導。
- 關卡完成時設為 `null`。

此欄位只存在於關卡執行中的 Session，不寫入 IndexedDB 闖關進度，因此不變更持久化 schema。

## 9. 純函式介面

建議在 `src/puzzle/puzzle-engine.ts` 新增純函式：

```ts
findNextPuzzleCell(
  session: PuzzleSession,
  currentCellKey: string,
  preferredPlacementId: string | null
): {
  readonly cellKey: string | null;
  readonly preferredPlacementId: string | null;
};
```

函式不得：

- 修改傳入 Session。
- 依賴 React、DOM 或瀏覽器尺寸。
- 使用非決定性亂數。

## 10. 資料流程

1. 玩家手動選格或沿用目前選取格。
2. 玩家點選候選字。
3. `placePuzzleTile` 驗證字牌可用並寫入目前格。
4. 重新計算正確格數與關卡狀態。
5. 若已完成，取消選取與方向偏好。
6. 若未完成，呼叫 `findNextPuzzleCell`。
7. 若盤面仍有空格，依同成語、交叉、相連、全盤最近順序找空格。
8. 若已無空格，依排序巡回錯誤格。
9. 更新 `selectedCellKey` 與 `preferredPlacementId`。
10. React 依新 Session 自動高亮下一格。

## 11. 例外與邊界行為

- 沒有選取格：不填字、不跳轉。
- 關卡已完成：不填字、不跳轉。
- 固定格或不存在的格：維持原 Session。
- 字牌不存在或已被使用：維持原 Session。
- 覆蓋目前格時，先釋放原字牌，再使用新字牌，之後才跳轉。
- 盤面資料異常導致找不到 placement 時，退回全盤最近空格；無空格時退回錯誤格巡回。
- 只有一個空格時，填入後若答錯且沒有其他空格，維持或循環選取該錯誤格。
- 玩家手動選擇已填正確格時，仍可選取，但下一次有效填字後會依正常規則跳轉；UI 是否禁止覆蓋正確格沿用現有行為。

## 12. 測試需求

至少新增以下自動測試：

1. 填對後沿橫向跳到右側下一個空格。
2. 填錯後原格保留錯字，但仍跳到下一個空格。
3. 自動略過固定提示格。
4. 自動略過已填正確格。
5. 盤面仍有空格時，自動略過已填錯誤格。
6. 目前方向沒有空格後切換到交叉 placement。
7. 交叉 placement 正向沒有空格時，選擇該 placement 其他空格。
8. 無相連空格時選擇曼哈頓距離最近空格。
9. 距離相同時依 row、column 穩定排序。
10. 全部空格填滿後跳到第一個錯誤格。
11. 修正錯誤格後跳到下一個錯誤格。
12. 修正排序最後的錯誤格後循環回第一個錯誤格。
13. 最後一個錯誤格修正後 `selectedCellKey` 與 `preferredPlacementId` 都為 `null`。
14. 手動選交叉格時依剩餘空格數量推導方向。
15. 空格數量相同時橫向優先。
16. 覆蓋錯字後原字牌回到候選池，並繼續跳轉。
17. 清空盤面後選取第一個可填格並重設方向。
18. `preferredPlacementId` 不影響既有進度保存格式。

既有 puzzle、progress、打地鼠與 PWA 測試必須全部維持通過。

## 13. 驗收標準

- 使用者可連續點選候選字完成多格輸入，不需逐格點盤面。
- 填錯後仍立即移動，錯字留在原格顯示紅色。
- 盤面有空格時，不會自動回到紅色錯字格。
- 所有空格填滿後，自動依固定順序逐一巡回錯誤格。
- 跳轉順序在相同 Session 下完全一致。
- 不會跳到固定提示格或已填正確格。
- 交叉格可依偏好方向順暢前進並在走完後轉向。
- 全部正確時正常進入既有過關與星級流程。
- `npm run test`、`npm run typecheck`、`npm run lint`、`npm run build` 全部通過。

## 14. 範圍限制

本次只修改填字盤面選取與 Session 跳轉行為，不變更：

- 關卡資料與答案。
- 星級計算規則。
- IndexedDB 進度格式。
- 自由接龍與打地鼠模式。
- 候選字視覺設計。
