# 第一章關卡成語全域不重複設計規格

## 0. 文件資訊

- Repository：`gshan1209-cell/Chinese-Idiom-Chain-Game`
- Branch：`feat/chapter-one-unique-idioms`
- 日期：2026-08-06
- 狀態：規格已核准，待實作計畫

## 1. 背景

第一章目前共有 20 關，總計 61 個成語 placement。現行 `LEVEL_CHAINS` 只引用 37 筆成語種子，導致同一成語在不同關卡重複出現。

本次調整的目標是：

> 第一章 20 關內，任何成語只能出現在一個關卡。

## 2. 核心規則

### 2.1 第一章唯一性

第一章全部 placement 必須同時符合：

- `idiomId` 全域唯一。
- 成語文字 `text` 全域唯一。
- 同一成語不得出現在兩個不同關卡。
- 同一關卡內也不得重複使用相同成語。

### 2.2 適用範圍

- 本規則只套用 `chapter-1`。
- 未來新增第二章時，是否可重新使用第一章成語另行設計。
- 本次不建立跨章全域唯一限制。

### 2.3 關卡結構維持不變

維持既有：

- 20 個關卡。
- 關卡 ID：`level-001`～`level-020`。
- 關卡編號與解鎖順序。
- 前期 2 個、中後期 3～4 個成語的難度梯度。
- 既有盤面交叉模式、固定提示格、提示上限與難度分級。
- 星級、解鎖、最高分與 IndexedDB 進度 schema。

玩家既有進度不需要重設或遷移。

## 3. 題庫與關卡資料

### 3.1 題庫容量

第一章需要 61 個唯一成語。正式資料至少提供：

- 61 個可用且互不重複的成語供第一章使用。
- 建議題庫擴充至至少 70 筆，保留替換、校訂與後續調整空間。

### 3.2 資料來源

主要維護來源：

- `data/idioms.source.csv`

生成資料：

- `public/generated/idioms.v1.json`
- `public/generated/idioms.manifest.json`

所有新增內容必須：

- 為四字繁體中文成語。
- 有非空白解釋。
- 通過既有資料驗證。
- 避免只為湊接龍而加入不可靠、罕見或未校訂詞條。
- 不將生成式 AI 未經人工確認的內容直接視為正式題庫。

## 4. 關卡配置策略

### 4.1 唯一成語鏈

重新配置 `src/puzzle/levels.ts` 的第一章鏈結，使 61 個 placement 各自引用不同成語。

每一關仍須滿足既有交叉規則：

- 第 1 個成語為橫向。
- 第 2 個成語由第 1 個成語末字交叉並向下。
- 第 3 個成語由第 2 個成語末字交叉並向右。
- 第 4 個成語由第 3 個成語末字交叉並向下。
- 每個交叉字必須完全一致。

### 4.2 難度梯度

- 第 1～5 關：維持 2 個成語。
- 第 6～12 關：維持 3 個成語。
- 第 13～20 關：維持現有 3～4 個成語配置。
- 不因唯一性調整而降低關卡數或縮減總 placement 數。

### 4.3 穩定識別

- `level.id`、`levelNumber` 與 `chapterId` 不變。
- placement ID 仍依關卡與位置產生。
- 成語 ID 必須保持字典內唯一。
- 題目內容變更不應改變玩家進度 key。

## 5. 永久驗證 Gate

在 `tests/puzzle-levels.test.mjs` 新增第一章全域唯一性測試：

1. 收集第一章所有 placements。
2. 斷言 placement 總數為 61。
3. 斷言 `idiomId` Set 大小等於 placement 數。
4. 斷言 `text` Set 大小等於 placement 數。
5. 斷言每個 placement 的成語存在於正式生成字典。

既有測試仍須全部保留：

- 恰好 20 關。
- 關卡編號連續。
- 每關盤面可成功建立。
- 交叉字一致。
- 候選字可完成整個關卡。
- 難度與成語數量依章節逐步增加。
- 不出現無法完成的死關。

## 6. 失敗處理

若新增題庫或關卡配置不符合規則：

- 資料建置應失敗，不生成不一致版本。
- Puzzle 測試應明確指出重複的 `idiomId` 或成語文字。
- 不允許以放寬唯一性、減少關卡或移除測試來通過 Gate。
