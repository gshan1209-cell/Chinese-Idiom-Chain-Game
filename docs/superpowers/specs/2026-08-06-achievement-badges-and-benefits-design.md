# 成就徽章與未來福利兌換設計規格

日期：2026-08-06  
Repository：`gshan1209-cell/Chinese-Idiom-Chain-Game`  
狀態：Approved  
建議實作分支：`feat/achievement-badges`  
任務類型：設計規格；本文件不包含 production code

## 1. 目標

為「中文成語填填字（CICG）」新增可長期擴充的成就系統：

1. 玩家完成闖關與學習目標時，獲得永久成就徽章。
2. 提供獨立的「成就殿堂」，讓玩家查看已取得與尚未完成的徽章。
3. 首版維持離線優先，不新增登入、後端或付費服務。
4. 架構預留未來福利機制，例如折價券、合作小物或活動兌換資格。
5. 真實福利不得直接信任可被修改的瀏覽器 IndexedDB 資料。
6. 首次取得徽章時，依子規格顯示成就特效與飛鏢轉盤式遊戲內獎勵。

核心原則：

> 徽章是永久榮譽，不會被消耗；未來可兌換的福利額度必須獨立管理。

## 2. 推薦方案與分期

採用「徽章、成就分數、福利點數三層分離」方案。

### 2.1 成就徽章

- 表示玩家完成過特定里程碑。
- 解鎖後永久保留。
- 不因兌換福利而消失。
- 首版保存在本機 IndexedDB。
- 可離線取得及瀏覽。

### 2.2 成就分數

- 用於成就殿堂的展示、總進度與收藏感。
- 由已解鎖徽章的分數加總而得。
- 首版沒有現金價值，不可兌換、轉讓或購買。
- 必須在 UI 清楚標示為「成就分數」，不得稱為現金、餘額或可用金額。

### 2.3 未來福利點數

- 與徽章及成就分數完全分離。
- 只有未來後端正式上線後才可啟用。
- 必須由伺服器核發、扣除、防重放並留下稽核紀錄。
- 可用於折價券、活動資格或福利小物，但不得信任本機 IndexedDB 直接兌換。

## 3. 首版徽章方向

首版規劃 14 枚徽章，涵蓋：

- 第一關完成。
- 完成 5、10、15、20 關。
- 累積星數里程碑。
- 三星通關里程碑。
- 零提示、零錯誤等完美表現。
- 已學成語數量里程碑。

實際名稱、圖示與條件由 Implementation Plan 依目前可可靠取得的進度資料定義，不得使用尚未存在或無法驗證的統計值。

## 4. 解鎖與保存原則

- 成就條件只由純 TypeScript 規則判定。
- React 不得自行解鎖徽章。
- 同一徽章只能首次解鎖一次。
- 解鎖時間、來源事件與成就版本必須保存。
- 重設第一章闖關進度不得刪除已取得徽章。
- 損壞資料必須安全回復，不得造成重複發放。

## 5. 成就通知

通知只能在安全節點出現：

- 關卡結算後。
- 自由接龍結束後。
- 打地鼠回合結束後。
- 成就殿堂主動查看時。

不得在填字輸入、智慧跳格、自由接龍答題或打地鼠倒數期間中斷玩家。

首次解鎖時的完整特效與飛鏢轉盤流程，依下列子規格執行：

```text
docs/superpowers/specs/2026-08-06-achievement-celebration-and-dart-rewards-design.md
```

## 6. 資料與架構

建議使用獨立資料庫，避免修改既有 `cicg-progress` schema：

```text
Database：cicg-achievements
Version：1
```

至少保存：

- 已解鎖徽章。
- 成就版本。
- 解鎖時間。
- 待顯示通知。
- 待慶祝佇列。
- 遊戲內獎勵轉盤機會與庫存。

真實折價券或實體福利資料不得以此本機資料庫作為可信核發來源。

## 7. 廣告與福利限制

- 看廣告不得取得徽章。
- 點擊推薦內容不得取得徽章。
- 看廣告或點推薦內容不得取得福利點數或轉盤機會。
- 首版不得導入真實折價券、付款、登入、後端或追蹤。
- 成就不得要求付費才能解鎖。

## 8. 測試與永久 Gate

至少驗證：

- 每項條件邊界。
- 同一徽章不重複解鎖。
- 重設進度不刪除徽章。
- 損壞資料安全處理。
- 通知只在安全節點顯示。
- 成就不改變星級、分數、提示或關卡進度。
- 廣告與推薦內容不發放徽章或福利。
- 子規格的獎勵結果不重抽、不遺失、不重複發放。
