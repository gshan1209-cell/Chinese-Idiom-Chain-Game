# 進階陷阱模式設計規格

日期：2026-08-06  
Repository：`gshan1209-cell/Chinese-Idiom-Chain-Game`  
狀態：Approved  
建議實作分支：`feat/advanced-trap-mode`  
任務類型：設計規格；本文件不包含 production code

## 1. 目標

為「縱橫成語填字」新增可選的進階陷阱玩法。陷阱分成三個進階層級：

1. **候選偽字**：系統偷偷在候選字池混入多餘字牌。
2. **盤面伏字**：假字直接出現在尚未完成的成語格內，單擊即可踢出。
3. **頑固伏字**：更高階的假字直接佔據尚未完成的成語格，必須連續點擊才能拔除。

陷阱會偶爾以輕微晃動、邊框變化或裂紋提示露出馬腳。玩家成功拔除時，假字會飛出畫面並播放短促的「踢出去」音效。

核心原則：

> 陷阱只增加辨識與反應挑戰，不修改正確答案、不製造死局、不算玩家失誤，也不破壞智慧自動跳格。

---

## 2. 模式分級

### 2.1 標準模式

- 沿用既有填字玩法。
- 不生成任何陷阱。
- 永遠是預設選項。

### 2.2 陷阱模式：候選偽字

- 系統在候選字池中動態加入 1～4 張多餘字牌。
- 假字不屬於本關任何答案。
- 玩家點擊後，字牌被踢出候選區。

建議解鎖條件：完成第一章第 5 關。

### 2.3 極限陷阱：盤面伏字

- 除候選偽字外，系統還會將假字直接放進尚未完成的成語格。
- 假字看起來像盤面上的一般文字，但會偶爾露出馬腳。
- 玩家單擊該格中的假字即可將它踢出。

建議解鎖條件：完成第一章第 10 關。

### 2.4 頑固陷阱：頑固伏字

- 包含候選偽字與盤面伏字規則。
- 部分盤面伏字會升級為頑固伏字。
- 頑固伏字必須在限定時間內連續點擊，才會完全拔除。
- 每次有效點擊都會讓假字出現更明顯的鬆動、裂紋或晃動。
- 最後一次有效點擊才播放完整飛出動畫與踢出音效。

建議解鎖條件：完成第一章第 15 關。

### 2.5 遊玩模式型別

不得修改既有關卡資料難度：

```ts
export type PuzzleDifficulty = 'easy' | 'normal' | 'hard';
```

陷阱屬於遊玩修飾器，建議新增：

```ts
export type PuzzlePlayMode =
  | 'standard'
  | 'trap-candidates'
  | 'trap-board'
  | 'trap-stubborn';
```

## 3. 永久公平原則

陷阱不得：

- 修改 `PuzzleCell.answer`
- 修改關卡 placement
- 修改候選合法字數量
- 移除合法字牌
- 取代固定提示格
- 改寫玩家已填入的正確字
- 增加 `mistakes`
- 扣除分數
- 增加 `hintsUsed`
- 改變星級門檻
- 因點擊陷阱而觸發智慧自動跳格
- 讓關卡無法完成
- 寫入第一章 61 個成語唯一性資料

標準模式與陷阱模式的星級規則保持一致。

陷阱本身不提供額外分數，避免不同模式的最佳分數失去可比較性。

## 4. 系統架構

陷阱狀態必須與 `PuzzleSession` 分離。

建議目錄：

```text
src/domain/trap.ts
src/traps/trap-engine.ts
src/traps/trap-plan.ts
src/app/use-trap-mode.ts
src/app/TrapTile.tsx
src/app/BoardIntruder.tsx
src/app/StubbornIntruder.tsx
```

### 4.1 純 TypeScript 責任

`src/traps` 負責：

- 陷阱字元生成
- 安全字元過濾
- 插入門檻
- 陷阱狀態機
- 露餡排程
- 點擊驅逐結果
- 頑固伏字連擊判定
- 點擊時間窗口判定
- 候選偽字、盤面伏字與頑固伏字數量限制
- 決定性與測試注入

不得依賴：

- React
- DOM
- CSS
- Web Audio
- `navigator.vibrate`
- 畫面尺寸
- IndexedDB
- 直接呼叫 `Date.now()`
- 散落的 `Math.random()`

時間與亂數必須以可測試介面注入。

### 4.2 React 與瀏覽器責任

`src/app` 負責：

- 呈現陷阱
- 飛出動畫
- 輕微露餡動畫
- 顯示頑固伏字受擊階段
- 播放本機音效
- 選擇性觸覺回饋
- reduced-motion 替代效果
- 動畫完成後通知引擎

React 不得自行決定陷阱生成、數量、有效性、連擊成功或排程。

## 5. 建議領域模型

```ts
export type TrapKind =
  | 'candidate-decoy'
  | 'board-intruder'
  | 'stubborn-intruder';

export type TrapStatus =
  | 'scheduled'
  | 'active'
  | 'revealing'
  | 'loosening'
  | 'ejecting'
  | 'removed';

export interface PuzzleTrap {
  readonly id: string;
  readonly kind: TrapKind;
  readonly character: string;
  readonly status: TrapStatus;
  readonly targetCellKey: string | null;
  readonly activationThreshold: number;
  readonly revealAfterActionCount: number;
  readonly revealCount: number;
  readonly requiredHitCount: number;
  readonly currentHitStreak: number;
  readonly lastHitAtMs: number | null;
}

export interface TrapSession {
  readonly mode: PuzzlePlayMode;
  readonly traps: readonly PuzzleTrap[];
  readonly validPlacementsCompleted: number;
  readonly ejectedTrapIds: readonly string[];
  readonly activeRevealTrapId: string | null;
}
```

### 5.1 盤面陷阱不是玩家輸入

盤面伏字與頑固伏字不得寫入：

- `PuzzleSession.values`
- `PuzzleSession.tileByCell`
- `PuzzleTile.usedBy`
- `correctCells`

它們只是渲染在格子上方的陷阱覆蓋層。

## 6. 候選偽字規則

### 6.1 數量

```text
候選偽字數量 = clamp(ceil(fillableCellCount × 0.18), 1, 4)
```

### 6.2 字元來源

候選偽字必須：

- 是單一繁體中文字
- 來自已啟用且通過資料建置的成語字典
- 不屬於本關任何答案字元
- 不與合法候選字元重複
- 不與同關其他陷阱重複
- 不使用遠端 API

安全字元不足時，減少陷阱數量，不得使用答案字元補足。

### 6.3 插入時機

陷阱依合法填字進度動態加入，不在開局一次全部顯示。

建議門檻：

| 陷阱總數 | 插入門檻 |
|---:|---|
| 1 | 25% |
| 2 | 20%、55% |
| 3 | 15%、45%、70% |
| 4 | 12%、35%、58%、78% |

只有成功放入合法字牌才推進門檻。

以下操作不推進：

- 點擊陷阱
- 提示
- 移除
- 重排
- 清空
- 無效操作

### 6.4 點擊結果

點擊候選偽字時：

- 不放入盤面
- 不增加錯誤
- 不扣分
- 不改變選取格
- 不改變偏好 placement
- 不觸發自動跳格
- 陷阱進入 `ejecting`
- 動畫結束後進入 `removed`

---

## 7. 一般盤面伏字規則

### 7.1 出現位置

盤面伏字只能出現在：

- 尚未填入玩家答案的可填格
- 非固定提示格
- 非目前正在播放其他陷阱動畫的格子

不得出現在：

- 固定格
- 已填正確或錯誤字的格子
- 已完成關卡
- 關卡完成動畫期間

### 7.2 數量上限

```text
一般盤面伏字數量 = clamp(ceil(fillableCellCount × 0.10), 1, 3)
```

同一時間最多 2 個 `active` 一般盤面伏字。

### 7.3 字元選擇

盤面伏字字元必須：

- 不等於目標格答案
- 不屬於本關合法候選字
- 不與目前其他陷阱重複
- 為已核准繁體中文字

### 7.4 單擊拔除

玩家直接點擊一般盤面伏字時：

- 伏字進入 `ejecting`
- 播放飛出動畫及踢出音效
- 格子恢復空白
- 保持原本選取格狀態
- 不算錯誤
- 不扣分
- 不跳格

若該格原本不是選取格，點擊陷阱不得順便選取該格。

---

## 8. 頑固伏字規則

### 8.1 出現位置

頑固伏字沿用一般盤面伏字的位置限制，並額外要求：

- 同一時間最多存在 1 個 `active` 頑固伏字。
- 不得與一般盤面伏字出現在同一格。
- 不得出現在目前選取格。
- 不得出現在智慧跳格即將前往的下一格。
- 不得在剩餘可填格少於 2 格時新增。

### 8.2 每關數量

```text
頑固伏字總數 = clamp(ceil(fillableCellCount × 0.06), 1, 2)
```

第一章單關最多 2 個頑固伏字。

安全位置不足時應減少數量，不得強制生成。

### 8.3 預設拔除條件

每個頑固伏字預設需要：

```text
requiredHitCount = 3
consecutiveHitWindowMs = 700
minimumAcceptedTapGapMs = 80
```

規則：

1. 第一次有效點擊開始連擊窗口。
2. 下一次點擊必須在 700ms 內完成。
3. 每次點擊至少間隔 80ms，避免同一個事件或快速抖動被重複計算。
4. 連續達到 3 次有效點擊後才可拔除。
5. 任一點擊超過 700ms，`currentHitStreak` 重設為 1，該次點擊成為新的第一擊。
6. 不得因滑鼠雙擊事件額外增加計數；只接受標準化後的單次啟動事件。
7. 觸控、滑鼠、Enter 與 Space 必須使用同一套核心判定。

### 8.4 輔助操作窗口

為支援較慢的連續操作，設定頁可提供：

```text
標準連點窗口：700ms
寬鬆連點窗口：1200ms
```

寬鬆模式仍需完成 3 次連續操作，不得退化為單擊拔除。

此設定只改變輸入窗口，不改變星級、分數或陷阱數量。

### 8.5 每次點擊的視覺回饋

建議分為三階段：

| 連擊 | 視覺狀態 | 音效 |
|---:|---|---|
| 第 1 擊 | 輕微抖動、出現細裂紋 | 短促「叩」聲 |
| 第 2 擊 | 晃動略增、裂紋加深、字體短暫傾斜 | 較重「咚」聲 |
| 第 3 擊 | 向外彈出、旋轉或滑出畫面 | 「咻＋碰」踢出聲 |

不得震動整個盤面或讓合法字一起晃動。

### 8.6 點擊攔截

每次點擊頑固伏字時：

- 不選取該格
- 不放入候選字牌
- 不增加錯誤
- 不扣分
- 不增加提示次數
- 不改變偏好 placement
- 不觸發智慧自動跳格
- 不觸發一般盤面格事件

頑固伏字必須阻止事件穿透至下方格子。

### 8.7 中斷連擊

連擊中斷時：

- 假字不消失。
- 不算錯誤。
- 不播放失敗音效。
- 裂紋回到第一階段前的狀態。
- 下一次點擊重新開始計數。

可使用一次很輕的回彈，表示它又卡回去了。

### 8.8 玩家嘗試填字

手動遊玩時，頑固伏字未拔除前不得接受該格的合法字牌。

若玩家選取其他方式指向該格並嘗試放入字牌：

- 字牌保持未使用。
- 不算錯誤。
- 不跳格。
- 頑固伏字播放一次明顯露餡提示。
- 顯示簡短提示：「先把怪字拔掉」。

不得自動替玩家完成三連擊。

### 8.9 提示功能的保底行為

為確保關卡永遠可完成，若系統提示選中有頑固伏字的格子：

1. 頑固伏字先播放快速拔除效果。
2. 正確提示字照常填入。
3. `hintsUsed` 依既有規則增加。
4. 不記錄為玩家手動拔除。
5. 不增加錯誤或額外扣分。

### 8.10 背景切換與暫停

切到背景或失去頁面可見性時：

- 尚未完成的連擊窗口立即失效。
- `currentHitStreak` 重設為 0。
- 不自動拔除陷阱。
- 回到前景後必須重新連擊。

避免玩家透過暫停時間繞過連續操作要求。

## 9. 智慧自動跳格與完成條件

智慧自動跳格仍以真實 `PuzzleSession` 判斷空格。

盤面伏字不得被視為已填字，因此：

- 必要答案格仍屬空格。
- 一般盤面伏字所在格可接受合法字牌並自動驅逐一般伏字。
- 頑固伏字所在格在手動填字前必須先拔除。
- 智慧導航不可因陷阱而永久跳過必要答案格。

當導航即將選到有頑固伏字的格子時：

- 該格可成為選取目標。
- UI 必須把輸入焦點優先交給頑固伏字。
- 玩家完成三連擊後，格子保持選取狀態，可直接繼續填字。

盤面全部正確時，關卡立即完成。

尚未啟用或仍在排程中的陷阱直接取消，不得阻擋完成流程。

## 10. 露出馬腳效果

### 10.1 視覺露餡

陷阱偶爾播放輕微左右晃動：

- 位移建議不超過 2px
- 總長 180～260ms
- 最多 2～3 次快速偏移
- 不使用整個畫面震動
- 不讓合法字牌一起震動
- 同一時間最多一個陷阱露餡

頑固伏字可額外出現：

- 1px 不規則位移
- 50～100ms 字體傾斜
- 細小裂紋
- 邊框短暫變深

不得使用高頻閃爍。

### 10.2 露餡頻率

建議每個陷阱啟用後，經過 3～7 次玩家有效操作觸發一次露餡。

- 不使用無限制高頻 timer
- 背景分頁不累積露餡動畫
- 每個陷阱最多自然露餡 3 次
- 玩家嘗試在頑固伏字格填字時可立即露餡一次
- 玩家停滯 5 秒以上時，可讓目前最需要處理的陷阱露餡一次

### 10.3 決定性排程

陷阱計畫應由純函式建立。

允許透過注入的 seed 產生變化，但不得直接在核心引擎內散落 `Math.random()`。

相同：

```text
levelId + mode + seed
```

必須產生相同的：

- 陷阱字元
- 插入門檻
- 盤面目標格
- 陷阱種類
- 露餡操作序列
- 頑固伏字數量

### 10.4 Reduced Motion

當 `prefers-reduced-motion: reduce`：

- 禁止位移飛行與快速晃動
- 露餡改為 250ms 邊框加深或明暗脈衝
- 每次受擊以裂紋階段與文字狀態呈現
- 驅逐改為快速淡出
- 仍需完成相同點擊次數
- 音效依使用者音效設定決定

## 11. 音效與觸覺回饋

### 11.1 音效

音效使用本機靜態素材，不從遠端載入。

至少需要：

- `trap-hit-light`
- `trap-hit-heavy`
- `trap-eject`

要求：

- 每段建議短於 500ms
- 玩家互動後才可播放
- 支援全域音效開關
- 不可蓋過成語電台或 YouTube 主要音量
- 若媒體中心正在播放，陷阱音效以短促前景效果播放，不改變媒體播放狀態
- 連續點擊不得造成音效疊加爆音
- 使用音效池或節流，避免同一音效重複建立大量物件

### 11.2 觸覺回饋

裝置支援且使用者開啟時，可使用：

```text
第 1、2 擊：不震動或最多 5ms
成功拔除：10ms
```

- 不支援時靜默略過。
- 不得影響功能。
- 不得以連續長震動代替視覺回饋。
- reduced-motion 不等於關閉觸覺；應由獨立設定控制。

## 12. 進度、星級與保存

首版不修改既有 `cicg-progress` schema。

以下資料不需要保存：

- 單局陷阱位置
- 連擊進度
- 露餡排程
- 目前陷阱狀態

離開或重新整理關卡後，陷阱依同一 seed 重新建立即可。

可保存的使用者設定：

- 上次選擇的遊玩模式
- 標準或寬鬆連點窗口
- 音效開關
- 觸覺回饋開關

設定應放入獨立設定儲存，不修改第一章進度格式。

星級與最佳紀錄沿用現有規則；陷阱拔除數不得影響星級。

---

## 13. 無障礙與手機操作

- 陷阱點擊區域至少 44×44px。
- 主要盤面仍需符合大字體設計。
- 鍵盤使用 Enter 或 Space 連續觸發。
- 每次有效擊中以 `aria-live="polite"` 回報，例如「頑固字，還要 2 次」。
- 成功拔除回報「已拔除怪字」。
- 不使用只有顏色才能辨識的狀態。
- 裂紋、邊框、文字狀態與音效至少提供兩種回饋。
- 360px 寬度不得出現水平捲動。
- 不要求多點觸控。
- 不使用長按作為唯一操作。

## 14. TDD 測試要求

### 14.1 候選偽字

至少驗證：

1. 偽字不屬於關卡答案。
2. 偽字不取代合法候選字。
3. 點擊偽字不更新 `PuzzleSession`。
4. 點擊偽字不增加錯誤、提示或扣分。
5. 點擊偽字不觸發智慧跳格。
6. 相同 seed 產生相同計畫。

### 14.2 一般盤面伏字

至少驗證：

1. 只出現在未填可填格。
2. 不出現在固定格或已填格。
3. 單擊後進入驅逐狀態。
4. 單擊不選取下方格子。
5. 合法字牌可正常填入並驅逐一般伏字。
6. 不寫入 `PuzzleSession.values`。

16. 背景切換會重設未完成連擊。
